# Бой MVP

## PvE-боты

Миграция `0004` переносит характеристики уже созданных шаблонов на общие
`Stat definitions`. Для нового бота в `/admin` создайте **Bot template** с
уникальным `code` и названием; оставьте `is_active=false`. В **Bot stats**
добавьте по одной связи с общими определениями `max_health`, `health`, `attack`,
`defense` и задайте значения. `health` не должен превышать `max_health`.
Дополнительные характеристики добавляются там же. В **Bot actions** свяжите
шаблон с существующим действием `basic_attack`, задайте `priority=0`. Затем
включите шаблон (`is_active=true`). Активные корректно настроенные шаблоны
доступны игроку как цели; API возвращает их характеристики в объекте `stats`.
Для нового умения сначала настройте **Action definition** и его эффекты через
**Effect definitions**, **Effect rules** и **Action effects**, затем добавьте
действие в **Bot actions**. Сейчас бот применяет только первое доступное действие
по возрастанию `priority`; условия выбора и случайность ещё не реализованы.

Игрок может выбрать активный шаблон через `GET /api/v1/fights/bot-targets` и
начать бой запросом `POST /api/v1/fights/bots` с `bot_template_id`. Каждый бой
получает собственный экземпляр бота (`source_type=bot` и новый `source_id`),
поэтому один шаблон может участвовать в нескольких боях одновременно. Исходный
шаблон записывается в `bot_template_id` участника, а параметры и действия
копируются в бой. Здоровье бота между боями не сохраняется.

Бот ходит сразу после действия игрока, выбирая первое доступное действие по
`priority` связей шаблона. Цель определяется `target_policy` действия. Результат
считается общим движком и попадает в `fight_actions` и `fight_events`. Сейчас
поддерживаются дуэли: игрок против игрока или игрок против бота.

## Старт и снимок

Бой начинается сразу после нападения одного живого свободного персонажа на
другого. Один источник может участвовать только в одном активном бою — это
гарантирует partial unique index.

В бой копируются характеристики, доступные actions и полные definitions их
эффектов. Последующее редактирование контента не меняет идущий бой. Участник
хранит `source_type/source_id`, поэтому движок не зависит от модели персонажа и
в будущем сможет получить снимок моба через другой provider.

## Ходы

- первый ход принадлежит атакующему;
- дедлайн каждого хода — 30 секунд;
- истечение срока пропускает ход и записывает `turn.timed_out`;
- polling разрешает только один просроченный ход и назначает новый полный
  дедлайн следующему игроку;
- команды содержат `expected_version` и `idempotency_key`.

## Действия

`basic_attack` меняет ресурс `health` через опубликованное expression rule:

```text
base_damage = max(1, source.attack - target.defense)
roll = random_int(90, 110)
damage = max(1, round_half_up(base_damage * roll / 100))
```

`rage` тратит ход и умножает `attack` на `1.25` в течение двух следующих
собственных ходов. Повторное применение обновляет длительность. Таймаут также
расходует один собственный ход эффекта.

Формулы обрабатывает собственный AST-интерпретатор без `eval`. RNG seed и
счётчик хранятся вместе с боем, а использованное значение записывается в событие.

## Завершение

При нулевом `health` бой завершается немедленно. Постоянный HP рассчитывается
для каждого персонажа как:

```text
ratio = battle_health / effective_battle_max_health
new_health = min(health_before_battle, round_half_up(persistent_max_health * ratio))
```

После finalization участники освобождаются для следующего боя. Журнал
`fight_events` является источником обновлений для REST polling и будущего
WebSocket publisher.
