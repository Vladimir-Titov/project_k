# Спецификация боя v1

## 1. Назначение и границы

Первая версия описывает чистое ядро пошагового боя:

```text
один персонаж против одного монстра
```

Спецификация определяет правила и ожидаемый интерфейс будущего боевого движка,
но не его хранение, HTTP API или доставку событий клиенту.

## 2. Участники

Персонаж и монстр представлены единым состоянием участника:

```text
id
participant_type
max_health
current_health
attack
defense
is_defending
```

Допустимые типы:

```text
character
monster
```

Правила:

* `max_health > 0`;
* `0 <= current_health <= max_health`;
* `attack >= 0`;
* `defense >= 0`;
* состояние участника фиксируется при создании боя и не читается движком
  напрямую из базы данных.

## 3. Жизненный цикл боя

Минимальные состояния:

```text
WAITING_FOR_PLAYER
RESOLVING_TURN
FINISHED
```

Последовательность:

1. Бой начинается в состоянии `WAITING_FOR_PLAYER`.
2. Первый ход всегда принадлежит игроку.
3. Игрок выбирает `attack` или `defend`.
4. Если монстр остался жив, он автоматически выполняет `attack`.
5. Если персонаж остался жив, начинается следующий ход игрока.
6. Шаги повторяются до достижения одним из участников нулевого здоровья.

Монстр в первой версии всегда атакует и не использует защиту.

## 4. Действия

### Обычная атака

Команда:

```text
attack
```

Базовый урон:

```text
base_damage = max(1, attacker.attack - defender.defense)
```

Для каждой атаки RNG возвращает целое значение от 90 до 110 включительно:

```text
damage_percent = random_integer(90, 110)
```

Итоговый урон:

```text
damage = max(1, round_half_up(base_damage * damage_percent / 100))
```

Используется округление до ближайшего целого, при значении ровно `.5` —
вверх. Банковское округление не используется.

Если цель находится в состоянии защиты:

```text
damage = max(1, ceil(damage / 2))
```

После получения этого удара защита снимается.

Новое здоровье:

```text
target.current_health = max(0, target.current_health - damage)
```

Промахи, критические удары и дополнительный минимальный урон в первой версии
отсутствуют.

### Защита

Команда:

```text
defend
```

Правила:

* защита выполняется вместо атаки;
* участник получает `is_defending = true`;
* следующий входящий удар наносит на 50% меньше урона;
* после первого входящего удара защита снимается;
* защита не переносится за пределы текущего боя.

Поскольку после действия игрока монстр атакует автоматически, защита игрока
обычно применяется к ближайшей атаке монстра.

## 5. Таймер хода

На выбор действия игроку даётся 30 секунд.

Если время истекло:

1. создаётся системная команда тайм-аута;
2. игрок пропускает ход;
3. защита автоматически не применяется;
4. монстр выполняет обычную атаку;
5. при выживании персонажа начинается новый ход с новым таймером.

Боевой движок не запускает таймеры и не использует `sleep`. Он получает текущее
время извне и проверяет его относительно `turn_deadline_at`.

Команда игрока, полученная после дедлайна, не выполняется и должна завершиться
ошибкой `TURN_EXPIRED`. После этого вызывающая сторона разрешает системную
команду тайм-аута.

## 6. Завершение боя

Бой завершается немедленно, когда здоровье участника становится равным нулю.

Результат содержит:

```text
winner_id
loser_id
finish_reason = defeated
```

После завершения:

* дополнительные действия запрещены;
* автоматический ответный ход не выполняется;
* ничья невозможна, поскольку действия разрешаются последовательно.

## 7. Детерминизм и интерфейс движка

Ожидаемый интерфейс чистого движка:

```python
def resolve_action(
    battle: BattleState,
    command: BattleCommand,
    rng: Random,
    now: datetime,
) -> BattleResult:
    ...
```

Движок:

* не зависит от FastAPI и SQLAlchemy;
* не обращается к базе данных;
* не создаёт RNG и не получает системное время самостоятельно;
* принимает полностью подготовленное состояние;
* возвращает новое состояние и список игровых событий;
* не изменяет переданное состояние на месте;
* при одинаковом состоянии, команде, времени и состоянии RNG возвращает
  одинаковый результат.

Random seed создаётся и хранится вызывающей стороной. Это необходимо для
тестирования, воспроизведения боя и симуляции баланса.

## 8. Команды и ошибки

Команды игрока:

```text
attack
defend
```

Системная команда:

```text
player_timeout
```

Минимальные ошибки:

```text
BATTLE_FINISHED
INVALID_ACTION
NOT_PLAYER_TURN
TURN_EXPIRED
TIMEOUT_NOT_REACHED
INVALID_BATTLE_STATE
```

Невалидная команда не должна частично изменять состояние боя.

## 9. События

Движок возвращает упорядоченный список событий:

```text
battle.started
turn.started
action.performed
defense.applied
damage.dealt
defense.consumed
turn.timed_out
battle.finished
```

События описывают уже произошедший результат и не являются командами.

Событие нанесения урона должно содержать как минимум:

```text
attacker_id
target_id
base_damage
damage_percent
defense_applied
final_damage
target_health_before
target_health_after
```

## 10. Примеры

### Обычная атака

```text
Атака атакующего: 12
Защита цели: 4
Базовый урон: 8
RNG: 105%
Итог: round_half_up(8.4) = 8
```

### Атака по защищающейся цели

```text
Урон до защиты: 9
Защита: ceil(9 / 2) = 5
Итоговый урон: 5
Эффект защиты снимается
```

### Победа

```text
У цели 5 HP
Полученный урон: 8
Новое здоровье: 0
Бой завершается до ответного хода
```

### Тайм-аут

```text
Игрок не выбрал действие за 30 секунд
Ход игрока пропущен
Монстр выполняет attack
При выживании игрока начинается новый 30-секундный ход
```

## 11. Не входит в первую версию

* несколько участников с каждой стороны;
* PvP;
* инициатива и изменение порядка ходов;
* усиленная атака и активные способности;
* яд, кровотечение, оглушение и другие эффекты;
* критические удары, промахи и уклонение;
* предметы, экипировка и расходники;
* награды, опыт и изменение постоянного состояния персонажа;
* хранение боя в PostgreSQL;
* scheduler, WebSocket и HTTP API;
* AI монстра, отличающийся от постоянной атаки.

## 12. Критерии готовности будущей реализации

* при фиксированном RNG бой полностью воспроизводим;
* игрок всегда начинает бой;
* после каждого действия живого игрока монстр атакует автоматически;
* защита уменьшает ровно один следующий входящий удар;
* тайм-аут пропускает ход без автоматической защиты;
* участник с нулевым здоровьем не может действовать;
* движок можно тестировать и запускать без FastAPI и PostgreSQL.
