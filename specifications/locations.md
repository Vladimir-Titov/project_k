# Локации и переходы

## Поведение

Персонаж находится в одной локации. Нажатие на выход немедленно меняет локацию,
если сервер разрешил переход. После прибытия действует общий таймер до следующего
перехода. Это задержка между перемещениями, а не время пути.

Сервер хранит `characters.location_id` и `characters.next_movement_at` (UTC).
Ожидание не сбрасывается при чтении состояния, выходе из игры или перезапуске.
Фоновые задачи, маршруты и отдельная сущность путешествия не используются.

## Таблицы и админка

- `locations`: `code`, `title`, `description`, `image_url` и стандартные поля.
- `location_transitions`: `from_location_id`, `to_location_id`,
  `base_duration_seconds`, `is_enabled` и стандартные поля.

Связь направленная. Для обратной дороги нужна отдельная запись. Пара локаций
уникальна, переход в себя запрещён, длительность положительная. Архивные дороги,
отключённые дороги и архивные назначения не возвращаются в списке выходов.

В админке доступны Locations и Location transitions. Связи показываются названиями
локаций. У персонажа также отображается связь с текущей локацией. Изображение можно
задать URL или загрузить через существующий механизм S3 в админке.

## Характеристики

`movement_speed` — скорость перемещения, исходное значение 100 для всех классов и
существующих персонажей. Новые персонажи получают её из характеристик класса.
При добавлении нового класса задайте ему эту характеристику, как здоровье и другие
обязательные игровые характеристики.

`home_world` — числовая характеристика принадлежности: 1 — Терен, 2 — Сайран.
Отдельной таблицы миров нет. Выбор мира при создании героя пока не добавлен.

Задержка после прибытия:

```text
max(1, ceil(base_duration_seconds * 100 / movement_speed))
```

Использованная дорога определяет задержку. Она рассчитывается при успешном
перемещении и сохраняется как абсолютный срок. Последующее изменение скорости или
дороги не меняет уже запущенный таймер. Длительности в списке выходов — оценка
задержки после следующего перемещения по текущим настройкам.

## API

Для авторизованной сессии с выбранным персонажем:

- `GET /api/v1/locations/current` — `location`, `transitions`,
  `next_movement_at`, `server_time`.
- `POST /api/v1/locations/move` с `{"transition_id": "UUID"}` — новое состояние
  в том же формате.

У каждого выхода есть `id`, `destination`, `cooldown_seconds`.

Коды ошибок (409): `movement_cooldown`, `transition_unavailable`,
`location_unavailable`, `invalid_movement_speed`, `character_busy`.
Проверки включают таймер, связь с текущей локацией, архивность, доступность дороги,
положительную скорость и отсутствие активного боя. Начало боя и перемещение
блокируют одну и ту же запись персонажа; начало PvP блокирует обоих в порядке ID.
Все действия выполняются в транзакции существующего API unit of work.

## Миграция и стартовые данные

```sh
uv run alembic upgrade head
```

Миграция `0005` создаёт 13 локаций по playbook и двусторонние домашние цепочки:
город ↔ пригород ↔ лес ↔ каменоломни ↔ руины ↔ подступы к вратам.
Начальная задержка на каждой дороге — 30 секунд; редактируется в админке.
Миграция создаёт Серую межу без дорог. Загрузчик добавляет 4 отключённые связи с вратами; условия доступа — следующий этап.
Никаких новых правил PvP или фильтрации мобов эта миграция не вводит.

Существующим персонажам без прежней принадлежности назначаются Терен и Велдар.
Новые персонажи также начинают в Велдаре. Начального ожидания нет.
Для тестирования Сайрана можно сменить характеристику мира и локацию в админке.
Изображения и описания заполняются загрузчиком контента (см. ниже).
При downgrade новые характеристики сохраняются как контент, чтобы не удалить
возможные ссылки из боёв и правил.

## Проверки

`uv run pytest -q tests/modules/locations` проверяет сервис, формулу и генерацию SQL
миграции. Проверка SQL не заменяет применение миграции к PostgreSQL.

## Полное наполнение

Команда после миграций: `uv run python scripts/load_locations.py`.
Источник — `specifications/locations-content.json`: 13 описаний по лору и пути PNG
из актуального `project_k_web/static/manifest.json`.

Используются `.env` и окружение (`DB_*`, `S3_*`), по умолчанию — локальные настройки
проекта. Загрузчик размещает PNG в `images/locations/` с хешем в имени, проверяет
каждую публичную ссылку и SHA-256, затем транзакционно заполняет таблицы.
Существующие ID, архивность и настройки дорог сохраняются. Названия, описания и
image_url обновляются по JSON. Политика существующего bucket не меняется.

28 сентября 2026 в локальную `127.0.0.1:40321/postgres` применены миграции 0001–0005
и загружены 13 локаций, 20 включённых домашних связей и 4 отключённые связи Пограничья.
Фоны доступны через `http://127.0.0.1:9000/project-k/images/locations/`.
Повторная загрузка проверена: дублей нет, ID и настройки не изменились.
Для другого окружения задайте доступный frontend адрес `S3_PUBLIC_URL` и повторите
загрузку. Недостающие модули получены из origin/master; миграции с нуля и реальный API проверены.
