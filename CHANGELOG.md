### Добавлено

Контракт сверён с кодом; миграция для изменения документации не нужна.

- Локации и направленные дороги (`locations`, `location_transitions`), настройки длительности и изображений в админке. У героя сохраняются текущая локация и срок ожидания следующего перехода. Переход мгновенный; задержка не сбрасывается после выхода из игры. Скорость `movement_speed` изначально 100, принадлежность `home_world` — характеристика, без таблицы миров.
- API `GET /api/v1/locations/current` и `POST /api/v1/locations/move` (`transition_id`), серверная проверка таймера и блокировка одновременных действий. Миграция: `uv run alembic upgrade head` (`0002`); 13 локаций, домашние дороги по 30 секунд, существующие герои стартуют в Велдаре. Пограничье пока без дорог до реализации условий доступа. Подробности: `specifications/locations.md`.

- `PLAYBOOK.html` — единая точка входа для разработки: мир, стартовый scope, локации, PvP, классы, бой, снаряжение, интерфейс, арт и технические спецификации. Утверждённые требования отделены от предложений и текущего MVP; добавлены открытые решения и постоянные якоря разделов. Открывайте файл в браузере; `PLAYBOOK.md` содержит краткие ссылки. Межрепозиторные ссылки предполагают соседние каталоги `project_k` и `project_k_web`.
- В лор добавлена ссылка на playbook. Игровые модели и API не менялись, миграции не нужны.

## 2026-09-18

### Изменено

- В `/admin` исправлена загрузка вариантов в полях связей, в том числе **Bot stats → Bot template**: скрытый в списках ID больше не блокирует сортировку запроса выбора. После перезапуска приложения откройте **Bot stats**, создайте запись и выберите существующий шаблон и определение характеристики; миграция не нужна.
- Характеристики бота теперь задаются в `/admin` → **Bot stats** как связи шаблона с общими **Stat definitions** и числовыми значениями. Для боя нужны `max_health`, `health`, `attack`, `defense`; дополнительные характеристики можно привязывать тем же способом. В **Bot templates** остались код, название, описание и `is_active`. **Bot actions** по-прежнему связывает шаблон с общими **Action definitions**.
- `GET /api/v1/fights/bot-targets` возвращает объект `stats` с кодами и значениями характеристик вместо отдельных полей `max_health`, `attack`, `defense`. Активные шаблоны без обязательных или корректных значений не показываются как цели. Миграция `0004` переносит значения уже созданных ботов в новые связи и удаляет старые колонки: `uv run alembic upgrade head`. Новые боты миграцией не создаются; действующие бои используют свои прежние снимки.

## 2026-09-16

### Добавлено

- PvE-бои с ботами. `GET /api/v1/fights/bot-targets` показывает доступные шаблоны, `POST /api/v1/fights/bots` с `{"bot_template_id": "UUID"}` начинает бой выбранного персонажа с отдельным экземпляром бота. В бою остаются два участника. Ход бота выполняется автоматически сразу после хода игрока и записывается в обычный журнал событий.
- В `/admin` появились **Bot templates** (название, описание, здоровье, атака и защита) и **Bot actions** (действия шаблона в порядке `priority`). Миграция `0003` создаёт только таблицы и связь с участником боя: `uv run alembic upgrade head`. Чтобы завести бота, создайте неактивный шаблон, добавьте связь с существующим действием `basic_attack` в **Bot actions**, затем включите `is_active`. Пока бот выбирает первое доступное действие; изменения шаблона влияют только на новые бои.

### Добавлено

- Пробный каталог `content/skills.json`: 20 классовых умений и 26 эффектов с изображениями из `output/skill-icons/webp-256`. Маг получает 7 умений, воин 6, путешественник 7. Пропущены рывок, телепортация, защита союзников и разведка. `uv run python seed_content.py --dry-run` проверяет каталог, `uv run python seed_content.py` загружает иконки в RustFS и одной транзакцией назначает умения классам и существующим активным персонажам. Повторный запуск не создаёт дублей; характеристики персонажей сохраняются. Общие тестовые `basic_attack`/`rage` снимаются с этих классов и персонажей, старые определения остаются. Новые наборы используются со следующего боя. Подробности: `content/README.md`.
- Периодические правила `resource_delta` у эффектов `turns`: срабатывают в конце хода носителя, включая таймаут, до уменьшения длительности. Это даёт кровотечение, яд и постепенное восстановление через существующие модели и формулы. Смертельный тик завершает бой. После обновления нужно перезапустить приложение; новых миграций нет. Проверки: `uv run pytest -q`, тест импорта в локальную БД с откатом: `RUN_CONTENT_INTEGRATION=1 uv run pytest tests/modules/test_demo_content.py -q`.
- Локальное S3-хранилище RustFS `1.0.0-rc.6` в `docker-compose.yml`: постоянные Docker volumes, подготовка прав каталогов, healthcheck. Запуск: `docker compose up -d --wait rustfs`. S3 API: `http://127.0.0.1:9000`, консоль: `http://127.0.0.1:9001`. Локальные логин/пароль по умолчанию: `rustfsadmin` / `rustfsadmin`; меняются через `S3_ACCESS_KEY` и `S3_SECRET_KEY`. Порты доступны только с локального компьютера.
- Конфигурация `S3_*` в `.example.env`. Для существующей `.env` добавьте блок S3 из примера; для стандартной локальной конфигурации достаточно `S3_ENABLED=true` и `S3_INITIALIZE_LOCAL_BUCKET=true`. После `uv sync` перезапустите приложение (`uv run python -m app.main`). На старте оно создаст bucket `project-k`, если его нет, и разрешит анонимное чтение только `images/*`. Запись, удаление и просмотр списка файлов требуют ключей. Без `S3_ENABLED` приложение работает без хранилища.
- В `/admin` → **Action definitions** и **Effect definitions** → создание/редактирование появилось поле **Image** с загрузкой и предпросмотром. Выберите PNG, JPEG, WebP или GIF и сохраните форму: `image_url` заполнится автоматически. Лимиты: 5 МиБ (`S3_MAX_IMAGE_SIZE_BYTES`) и 16 мегапикселей, формат проверяется по содержимому файла. Ручной ввод **Image URL** сохранён; загруженный файл имеет приоритет. Флажок удаления снимает ссылку с определения. Старые файлы сохраняются, поскольку URL могут использоваться в снимках боёв; замена всегда создаёт новый уникальный файл.
- Отдельный контракт `FileRepository` и реализация `S3FileRepository` в `app/core/files`: `put`, `get`, `delete`, `public_url`. `ImageService` проверяет изображения и работает через контракт репозитория. Клиент подключается через фабрику приложения и lifespan, доступен как `application.state.files`, закрывается при остановке; S3-вызовы выполняются в пуле потоков. Для другого S3-сервиса задайте endpoint, bucket, region, ключи и публичный URL/CDN, отключите `S3_INITIALIZE_LOCAL_BUCKET` и настройте доступ к изображениям на стороне хранилища. Инициализация локального bucket заменяет его политику, поэтому предназначена только для разработки.
- Существующие `GET /api/v1/action-definitions`, `GET /api/v1/effect-definitions` и состояние боя возвращают сохранённые постоянные URL: браузер получает изображение напрямую из хранилища. `S3_PUBLIC_URL` должен быть доступен браузеру и включать bucket; при другом порте измените также `S3_ENDPOINT_URL` и `RUSTFS_API_PORT`. Новых миграций для загрузки нет; для ранее добавленного `image_url` нужна существующая миграция `0002` (`uv run alembic upgrade head`).
- Проверки загрузки через формы админки, сохранности записи при ошибках, репозитория и его lifecycle. Обычные тесты: `uv run pytest -q`; интеграционная проверка с запущенным локальным RustFS: `RUN_S3_INTEGRATION=1 uv run pytest tests/core/files/test_s3_integration.py -q` (создаёт локальный bucket/политику и удаляет свои временные файлы).

## 2026-09-14

### Добавлено

- Скрипт `autobattle.py` в корне для отладки боёв с врагом через API. Входит в существующий аккаунт, выбирает персонажа и действует только в свой ход. Поддерживает случайный выбор, одно действие (`--action CODE`) или повторяемую последовательность (`--actions CODE CODE ...`), задержку (`--delay`), адрес приложения (`--url`) и восстановление между боями (`--rest`). Запуск: `python3 autobattle.py --login enemy`.
- Необязательное поле `image_url` у `ActionDefinition` и `EffectDefinition`, доступное для редактирования в админке. Новые ручки `GET /api/v1/action-definitions` и `GET /api/v1/effect-definitions` возвращают активные, неархивные определения с URL картинки. В состоянии боя URL также возвращается у активных эффектов; для новых боёв он сохраняется в снимке определения. Миграция: `uv run alembic upgrade head` (ревизия `0002`).
- Этот changelog и правило в `AGENTS.md` обновлять его после каждой фичи.

### Изменено

- В `autobattle.py` автовосстановление здоровья включено по умолчанию: враг восстанавливается при запуске вне боя и после каждого боя. Запрос восстановления выполняется один раз между боями; если персонаж занят, скрипт повторяет попытку после следующего опроса. Отключение: `--no-rest`.
- В списках и формах админки связи с классами, персонажами, характеристиками, действиями, эффектами и участниками боя показываются по человекочитаемым названиям. Значимые поля идут первыми; служебные ID и даты доступны в карточках. Сохранена сортировка списков по дате создания. В `AGENTS.md` закреплено правило обновлять админку при изменении моделей.
