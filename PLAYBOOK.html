Playbook разработки

Общая точка входа в решения и материалы игры.

Как пользоваться

Единая точка входа для разработки Project K. Здесь собраны решения по игре, ссылки на подробный контент и состояние художественного набора. Обновлено 28 сентября 2026.

Статусы: «Утверждено» — продуктовые требования; «Предложение» — подготовленный контент для обсуждения; «Текущий MVP» — сведения из технических спецификаций. Утверждённое требование само по себе не означает, что функция уже реализована.

Перед задачей прочитайте соответствующий раздел и связанную спецификацию. При изменении решения обновляйте этот playbook, затем профильный документ и CHANGELOG. HTML — основной редактируемый документ; PLAYBOOK.md служит короткой ссылкой на него. Галерея хранит изображения, manifest — их ID, пути и точные промпты.

При расхождении целевого дизайна с текущим поведением оформляйте задачу на изменение. Не подменяйте один другим. Новые названия, числа баланса и механики не становятся утверждёнными автоматически.

Игра и границы первой версии

Утверждено Браузерная MMORPG с пошаговым боем. Игровой цикл: задания → опыт и уровни → бои с мобами → лучшее снаряжение. PvP происходит в общей территории.

  • Максимальный уровень игрока — 7. Мобы домашнего стартового набора — до 6-го уровня.
  • Два домашних мира, по шесть типов локаций в каждом, одна общая локация Пограничья.
  • Снаряжение: дроп с мобов и возможные награды за задания. Продажу экипировки в магазинах не считать утверждённым источником.
  • Инстансы и увеличение максимального уровня — позже, по развитию контента и числу игроков.
  • Захват ничейной территории возможен в будущем; первая версия от него не зависит.
  • Специальные PvE-цели в Пограничье на старте не нужны.

Миры и конфликт

Утверждено Множество миров существовало изначально. Никогда не было единого мира, его разделения, оригинала и копий. Миры долго развивались независимо, научились путешествовать и встретили похожие на себя народы. Несколько войн превратили вражду в постоянное состояние. Игрок приходит уже в эту эпоху.

География и жители похожи, но имеют небольшие различия. Языки достаточно близки для частичного понимания, сохраняя ощущение чужой речи. Оба мира защищены от прямых переходов противника; дороги между ними проходят через Пограничье.

Предложение «Созвучие», «Завеса», дорожная служба, история конкретных войн, культурные обычаи и реплики описаны в подробном лоре. Пограничье там трактуется как самостоятельный мир. Эти детали не вводят дополнительные игровые механики.

Локации и контент

Реализация переходов, 28 сентября 2026: персонаж сразу меняет локацию при успешной серверной проверке. После прибытия действует задержка до следующего перехода; срок сохраняется в БД и не сбрасывается при выходе. Дороги направленные, длительность редактируется в админке и зависит от характеристики скорости (база 100). Мир — характеристика героя; таблицы миров, маршрутов и путешествий нет. Добавлены 13 локаций и домашние цепочки; четыре связи Серой межи заполнены и отключены до введения условий доступа. Старт — Велдар. Модели, API и миграция. Недостающие модули получены из origin/master; проверен реальный API регистрации, создания героя и переходов.

Пограничье и PvP

Утверждено Вход с 3-го уровня. Свободное нападение по всей общей локации; мобы общие для обеих сторон. Отдельные безопасные участки у NPC или выходов не предусмотрены. Разговор с NPC не должен означать защиту от нападения.

«Нейтральное» здесь означает отсутствие общего владельца, а не мирную зону. На старте нет захвата точек и специальных PvE-целей. Домашние миры защищены от прямого перехода врага.

Свободное нападение — правило территории. Нападения на игроков своей стороны, возможность атаковать самих NPC, смерть, штрафы, возврат и защита от повторных нападений ещё требуют отдельных решений. Не выводить эти механики из лора.

Задания, опыт и снаряжение

Игрок выполняет задания, повышает уровень и получает лучшее снаряжение. Источники экипировки — мобы и задания. Конкретные награды в лоре — варианты наполнения, не утверждённые таблицы.

Подготовлены изображения короткого меча, посоха ученика, пары ножей, клёпаного жилета, куртки мага и нагрудника разведчика. Названия грейдов, слоты, характеристики, требования, шансы дропа и темп получения опыта пока не определены.

Наличие лавки на площади не означает, что торговля экипировкой уже входит в первую версию. Названия кнопок и предметы на концепте также не добавляют механику сами по себе.

Экран игрока

Утверждённое направление Средневековый рисованный игровой интерфейс: кожа, пергамент, металл и умеренное магическое свечение. У опций — узнаваемые предметные изображения: рюкзак для инвентаря, соответствующие символы для остальных разделов.

  • Сверху слева: персонаж, уровень, здоровье, энергия и опыт.
  • Сверху справа: рюкзак, локация, охота, статистика.
  • Центр: крупное изображение текущей локации.
  • Справа внутри области локации: переходы, NPC, таймер текущего действия.
  • У правого края: быстрые опции; состав ещё нужно определить.
  • Снизу: чат и список игроков в локации.

Предыдущие варианты: кожа и пергамент, камень и руны. Это макеты, а не подтверждение реализации нового интерфейса.

Загрузка и формат ответа

GET /api/v1/locations/current возвращает 200 и следующий объект. Пример иллюстративный: UUID дороги нужно брать из реального ответа.

{
  "location": {
    "id": "00000000-0000-0000-0000-000000009001",
    "code": "loc-teren-city",
    "title": "Велдар — Медный двор",
    "description": null,
    "image_url": null
  },
  "next_movement_at": "2026-09-28T12:00:30Z",
  "server_time": "2026-09-28T12:00:10Z",
  "transitions": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "destination": {
        "id": "00000000-0000-0000-0000-000000009003",
        "code": "loc-teren-suburb",
        "title": "Нижние сады",
        "description": null,
        "image_url": null
      },
      "cooldown_seconds": 30
    }
  ]
}

В примере осталось 20 секунд. Массив выходов возвращается и во время ожидания. Backend исключает отключённые и архивные дороги, а также архивные назначения. В элементах нет полей available и unavailable_reason: присутствие дороги в списке не гарантирует успех команды — при клике проверяются таймер, активный бой и актуальное состояние дороги.

Клик и обновление экрана

POST /api/v1/locations/move
Content-Type: application/json
Authorization: Bearer <access_token>

{"transition_id": "11111111-1111-4111-8111-111111111111"}
  1. На открытии экрана загрузить current; кешировать по ID выбранного героя, например ['location', characterId].
  2. Пока общий таймер больше нуля или запрос move выполняется, отключить кнопки переходов.
  3. При клике отправить ID дороги. Не менять локацию оптимистически: дождаться ответа сервера.
  4. При 200 ответ имеет тот же формат, что current: новая локация, выходы из неё, новый срок и время сервера. Полностью заменить состояние в кеше этим ответом. Дополнительный GET для подтверждения не нужен.
  5. При ошибке сохранить прежнюю локацию, показать сообщение и перечитать current. При сетевом сбое запрос мог успеть завершиться на сервере — сначала перечитать состояние, а не повторять команду автоматически.
  6. При возвращении в игру или на вкладку обновить current. Отсчёт в интерфейсе локальный; посекундный опрос backend, запрос завершения и автоматический следующий переход не нужны.

Расчёт отображаемого остатка

Сразу при получении каждого ответа сохранить локальное receivedAt = Date.now(). Это клиентское поле, его нет в JSON сервера. Так разница часов пользователя и сервера не меняет начальное ожидание.

elapsedMs = Math.max(0, Date.now() - receivedAt)
remainingSeconds = next_movement_at === null ? 0 : Math.max(0, Math.ceil(
  (Date.parse(next_movement_at) - Date.parse(server_time) - elapsedMs) / 1000
))

Значение обновляется локально, например каждые 250 мс. После сна вкладки вычислять остаток из абсолютного времени, а не уменьшать счётчик на единицу. В нуле только разрешается клик; окончательное решение принимает сервер. Новый запрос синхронизирует состояние после изменения локальных часов или перехода из другой вкладки.

Ошибки

Доменные ошибки имеют формат {"detail":"movement_cooldown"}. Ошибки валидации FastAPI (422), например некорректный UUID, имеют массив в detail.

HTTP / detailДействие frontend
409 / movement_cooldown«Время ожидания ещё не закончилось». Перечитать состояние и синхронизировать таймер.
409 / transition_unavailable«Этот переход больше недоступен». Обновить выходы: дорога могла измениться либо герой уже находится в другом месте.
409 / character_busy«Во время боя переходить нельзя». Обновить состояние игры.
409 / location_unavailable«Локация сейчас недоступна». Показать ошибку загрузки и возможность повторить запрос.

Полное наполнение локаций

Загружено и проверено 28 сентября 2026: локальная PostgreSQL 127.0.0.1:40321/postgres, схема frontiers: 13 локаций с названиями, описаниями и изображениями; 24 направленные связи (20 домашних включены, 4 связи Пограничья отключены), базовая задержка 30 секунд. У всех трёх классов скорость 100 и родной мир 1 (Терен).

Данные: locations-content.json. Описания подготовлены по лору, изображения взяты из актуального project_k_web/static/manifest.json. Загрузчик load_locations.py сохраняет PNG в RustFS и записывает готовые URL в таблицу. Все 13 изображений проверены чтением по публичной ссылке и сравнением хеша.

uv run python scripts/load_locations.py

Запускать после миграций; настройки берутся из .env и окружения DB_*, S3_*. Повторная загрузка проверена: дублей нет, существующие ID, архивность и настройки дорог сохраняются. Названия, описания и ссылки обновляются из JSON. Имена изображений включают хеш содержимого; одинаковые файлы не загружаются повторно. Существующая политика доступа bucket не заменяется.

Текущие URL начинаются с http://127.0.0.1:9000/project-k/images/locations/ и предназначены для локальной разработки. Для другого сервера задайте доступный браузеру S3_PUBLIC_URL и повторите загрузку в нужном окружении. Данные в базе заполнены; API проверен на настоящей PostgreSQL, включая сохранение таймера после перехода.

Готовые модули и границы реализации

  • locations.ts — типы, API, ключ кеша и receivedAt.
  • LocationPanel.tsx — готовая панель, подключена в GamePage.
  • countdown.ts — отсчёт; errors.ts — сообщения ошибок.
  • Спецификация локаций — таблицы, формула, админка и стартовые данные.

После миграции есть 13 локаций, домашние цепочки с базовой задержкой 30 секунд и старт в Велдаре без ожидания. Четыре связи Пограничья заполнены, но отключены. Условия мира, уровня и PvP, список игроков в локации, NPC и привязка мобов к локациям этим API не реализованы. Их нельзя выводить из списка переходов, названий или картинок. Сервер не строит маршруты: игрок выбирает один выход из текущей локации.

Техническая карта и текущий MVP

Этот раздел — указатель на существующие материалы, не полный аудит работоспособности. Состояние запущенной игры, миграций и базы в рамках подготовки playbook не проверялось.

ОбластьИсточникЧто учитывать
Персонажи и контентcharacter.mdКлассы, характеристики, действия, создание и восстановление. В текущем seed описаны adventurer, warrior, magician — это ещё не окончательная тройка дизайна.
Бойbattle.mdДуэли, снимки участников и контента, дедлайны, версии команд, боты. Текущий rage расходует ход; не переносить это правило на все будущие бафы.
APIОбщий router, бои, персонажиКонтракты уточнять в соответствующих schemas и коде; не из названий картинок.
FrontendREADME клиентаЗапуск, проверки, организация модулей и интеграция боевого контента.
ИсторияBackend, frontendЗавершённые изменения и инструкции, не будущий план.

В технической спецификации боя зафиксированы первый ход атакующего, дедлайн 30 секунд, expected_version и idempotency_key, копирование контента в бой и выбор ботом первого доступного действия по priority. Это описание текущего MVP; числовой баланс целевого набора классов ещё не утверждён.

Из проверенных маршрутов: GET /api/v1/fights/bot-targets, POST /api/v1/fights/bots, POST /api/v1/fights/{fight_id}/actions, GET /api/v1/character-classes. Полные тела запросов смотреть в schemas рядом с router.

Проверки backend: uv run pytest -q. Клиент: npm run typecheck, npm run lint, npm test, npm run build. Выполнять из соответствующего репозитория; подробности окружения — в документации клиента и конфигурации проекта.

Открытые решения

  • Окончательные названия классов, серверные коды и переход с текущего seed.
  • Мана / энергия, формулы, стоимости, длительности, перезарядки и повторение действий без завершения хода.
  • Цели бафов и правила напарников; наличие союзного бафа не означает готовые групповые бои.
  • Кривая опыта до 7, награды заданий, грейды и таблицы дропа.
  • Граф переходов и маршрут в Пограничье с 3-го уровня без обязательного боя с мобами 6.
  • Правила смерти, возвращения, нападений на своих и взаимодействия с NPC при угрозе PvP.
  • Состав быстрых опций, назначение таймеров, каналы чата и мобильная компоновка.
  • Утверждение предложенных имён NPC, мест, квестов и деталей истории.
  • Завершение 11 артов, затем интеграция изображений в реальные игровые данные и UI.

Этот список не расширяет scope первой версии. Решения принимаются по мере появления конкретных задач.

Правила изменения проекта

Следовать правилам backend и правилам frontend: простые решения, без преждевременных усложнений, сохранение совместимости, разделение UI на компоненты.

  • При изменении моделей сразу обновлять админку: ORM-связи, __admin_repr__, значимые поля и связи в начале форм и списков.
  • После законченного изменения обновлять CHANGELOG соответствующего репозитория: дата, результат, способ использования, нужные команды / API / миграции.
  • Для изменения дизайна игры обновлять соответствующий раздел playbook и профильную спецификацию. Указывать, что утверждено, что предложено и что реализовано.
  • Для арта обновлять файл, manifest и галерею; сохранять точный промпт и исходный вариант.
